# Test scenario TS-02: Invite a school admin, suspend and remove them

| | |
|---|---|
| **Purpose** | Verify that a school admin can invite a new school admin, that the new admin can sign in and out, that a suspended admin cannot sign in, and that an admin can be removed. |
| **Environment** | QA (the QA build of the Android app) |
| **Roles covered** | School admin (existing), school admin (new) |
| **Time needed** | About 20–30 minutes |
| **Background** | [roller.md](roller.md) explains the roles. |

---

## 1. Entry requirements

If something is missing, stop and report it. Do not work around it.

| # | Requirement | How to check |
|---|---|---|
| E1 | One Android phone with the QA build installed. Write down the version shown under More → Diagnostics. | The app opens and shows the sign-in screen. |
| P1 | A test school exists with **exactly one school admin: SA1**. | Ask the Virtual School team. |
| P2 | A second Google account, **SA2**, that is **not** staff at the test school. SA2 may already have a role at a *different* school. | Ask the Virtual School team. |

**SA1** and **SA2** both use the phone, one after the other. To switch accounts on the phone: tap the account button at the top right → "Sign out", then sign in with the next account.

---

## 2. Steps and expected results

Mark each step **Pass** or **Fail**. Text in "quotes" is the exact button or screen text.

**Automated column.** The Virtual School team runs these steps against the QA backend after each deploy (about 20 seconds, 17 checks, including all the "nobody may get more access" checks). **API** = the backend rule is checked automatically, so you only need to confirm that the app *shows* the expected result. **Manual only** = nothing checks this step automatically; do it carefully. Ask the team whether the latest automated run was green before you start. If it was not, stop and report it.

### Part A – Invite (SA1 App, SA2 App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| A1 | **SA1 (App):** sign in. Open "Staff". | Under "School admins" only SA1 is listed. | API |
| A2 | "Invite school admin" → choose "Write it down". | A code in the form `ABC-DEF-GHJ` is shown with "One-time · valid for 14 days". Write it down for SA2. | API |
| A3 | **SA2 (App):** sign in. SA2 has no role yet, so More shows "You're signed in, but this account doesn't have access to a class yet...". Tap "Have an invite code?", type the code from A2, but **change one character**, and tap "Continue". | "That code does not look right. Please check it against your slip." | API |
| A4 | Type the **correct** code into the three boxes (small or capital letters do not matter; the dashes between the boxes are only decoration, and a code pasted into the first box fills all three) and tap "Continue". **Do not tap "Join" yet.** | "You are invited" – "Join <school name> as a school admin." | API |
| A5 | **SA1 (App):** "Staff" → pull to refresh. | SA2 is **not** in the list yet. | API |
| A6 | **SA2 (App):** tap "Join". | "You're now a school admin" – "You have joined <school name> as a school admin." A "Continue" button is shown. | API |
| A7 | **SA2 (App):** tap "Continue". Then open More → "Have an invite code?" and type the same code again. | After "Continue" the school view opens (see B1). The old code gives "This invite is not valid." *(A used code is deleted, so it looks the same as an unknown code.)* | API |
| A8 | **SA1 (App):** "Staff" → pull to refresh. | SA2 is now listed under "School admins". | API |

### Part B – The new admin signs in and out (SA2, App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| B1 | **SA2 (App):** after A7 the app is already signed in. If not, sign in. | The school view opens with the tabs "Staff", "Classes", "Calendar" and "More". The school name is shown. | API |
| B2 | Open "Staff". | Both SA1 and SA2 are listed under "School admins". | API |
| B3 | Tap the account button at the top right → "Sign out". | SA2 is signed out and the sign-in screen is shown. | Manual only |

### Part C – Suspend (SA1 App, SA2 App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| C1 | **SA2 (App):** sign in again, so SA2 is signed in. | The school view opens. | Manual only |
| C2 | **SA1 (App):** "Staff" → tap SA2. Switch "Account active" **off**. | "Suspended — this person cannot use the app." | API |
| C3 | **SA2 (App):** sign out and try to sign in again. | SA2 **cannot** use the app. The screen says "Your account has been suspended. Contact your school administrator." with the buttons "Try again" and "Sign out". *(It must not say that the sign-in has expired. Allow up to 1 minute after C2 for the block to take effect.)* | API |
| C4 | **SA1 (App):** "Staff" → tap SA2 → switch "Account active" **on** again. **SA2 (App):** wait 1 minute, then sign in again. | The school view opens. *(Do not skip this step. A suspended account stays suspended after the admin role is removed, and nobody can switch it on again from the app. SA2 could then not be invited again.)* | API |

### Part D – Remove (SA1, App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| D1 | **SA1:** "Staff" → tap SA2 → "Remove admin". | The question "Remove <name> as school admin? They lose admin access to the school." is shown. | API |
| D2 | Cancel. | Nothing changes. SA2 is still listed. | Manual only |
| D3 | Repeat D1 and confirm. | SA2 is no longer under "School admins". | API |
| D4 | **SA2 (App):** try to sign in. | SA2 has **no** school view and no admin functions. *(Record what SA2 sees. If SA2 has a role at another school, that school may show.)* | API |
| D5 | **SA2 (App):** More → "Have an invite code?" → type the old code from A2. | "This invite is not valid." | API |
| D6 | **SA1:** open SA1's own detail page. | "Remove admin" is greyed out with "You can’t remove yourself as school admin — ask another admin." | API |

---

## 3. Pass criteria

The scenario **passes** when all of the following are true:

- Every step is marked Pass, except those that say "Record".
- No step showed a technical error ("Something went wrong", a number such as 403 or 500) unless the expected result said so.
- C4 passed. SA2 can sign in again after being switched on.
- The checks that nobody may get more access than they should all passed: A3, A5, A7, C3, D4 and D5. **Any failure here is serious. Report it first.**

## 4. When a step fails

Write down:

1. The step number (for example **C3**).
2. The account used and the device.
3. The time in Philippine time.
4. What you expected and what actually happened.
5. A screenshot. For app problems, also the version from More → Diagnostics.

## 5. After the test

The test school and its data stay in QA. SA2 is removed in D3, so SA1 is the only admin again and the scenario can be run again with a new code.
