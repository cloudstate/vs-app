# Test scenario TS-01: Create and delete an empty class

| | |
|---|---|
| **Purpose** | Verify that a school admin can create a class, that a second class with the same name is refused, that an empty class can be deleted, and that the name can be used again afterwards. |
| **Environment** | QA (the QA build of the Android app) |
| **Roles covered** | School admin |
| **Time needed** | About 10 minutes |
| **Background** | [roller.md](roller.md) explains the roles. [testscenario-oversikt.md](testscenario-oversikt.md) shows how this fits with the other scenarios. |

---

## 1. Entry requirements

If something is missing, stop and report it. Do not work around it.

| # | Requirement | How to check |
|---|---|---|
| E1 | One Android phone with the QA build installed. Write down the version shown under More → Diagnostics. | The app opens and shows the sign-in screen. |
| P1 | A test school with a school admin: **SA**. | Ask the Virtual School team. |
| P2 | The school has **no class** named "TS-01 Class A". | SA: "Classes". If the class exists from an earlier run, delete it first. |

---

## 2. Steps and expected results

Mark each step **Pass** or **Fail**. Text in "quotes" is the exact button or screen text.

**Automated column.** The Virtual School team runs these steps against the QA backend after each deploy (about 20 seconds). **API** = the backend rule is checked automatically, so you only need to confirm that the app *shows* the expected result. **Manual only** = nothing checks this step automatically; do it carefully. **API only** = there is no screen for this check; it is done automatically and you do not do it. Ask the team whether the latest automated run was green before you start. If it was not, stop and report it.

### Part A – Create (SA, App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| A1 | Sign in as **SA**. | The app opens on the school view with the tabs "Staff", "Classes", "Calendar" and "More". The school name is shown. | API |
| A2 | "Classes" → "Create class". Class name "TS-01 Class A", grade 3 → "Create". | The class appears in the list with 0 learners and "Not assigned" as homeroom teacher. | API |
| A3 | Try to create a second class with the **same name** "TS-01 Class A". | "A class with that name already exists at this school." The text disappears as soon as you change the name or the grade. | API (the text and its disappearing: look at the screen) |
| A4 | Try again with the name written differently: " ts-01 class a " (small letters, extra spaces). | It is refused with the same text as in A3. *(The automated run on 4 October 2026 recorded exactly this. If a second class is created, report it and delete it as in C3.)* | API |
| A5 | Try to create a class with an **empty** name. | It cannot be created. The "Create" button is disabled or an error is shown. | API |

### Part B – Look at the class (SA, App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| B1 | Open the class "TS-01 Class A". | The class shows its name, grade 3, "Not assigned" as homeroom teacher and no learners. | API |
| B2 | Go back to "Classes" and pull to refresh. | The class is still in the list, once. | API |

### Part C – Delete (SA, App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| C1 | Open the class → "Delete class". | A question asks you to confirm the deletion. | Manual only |
| C2 | Cancel. | Nothing changes. The class is still listed. | Manual only |
| C3 | Repeat C1 and confirm. | The class is gone from "Classes". | API |
| C4 | Create a class named "TS-01 Class A" again (as in A2). | It is created. *(The name must be free again after a deletion.)* | API |
| C5 | Delete this class too (as in C3). | The school has no "TS-01 Class A" again, so the scenario can be run again. | API |

### Checked automatically only (no screen)

These checks have no screen in the app, so a person cannot do them. They run automatically. Any failure here is serious.

| # | What is checked |
|---|---|
| D1 | An admin of **another school** can neither read nor delete this school's class, and cannot create one here. |
| D2 | A **teacher** of this school who has no class cannot read, create or delete a class. |

---

## 3. Pass criteria

The scenario **passes** when all of the following are true:

- Every step is marked Pass.
- No step showed a technical error ("Something went wrong", a number such as 403 or 500) unless the expected result said so.
- C4 passed. The name is free again after a deletion.
- The latest automated run (including D1 and D2) was green.

## 4. When a step fails

Write down:

1. The step number (for example **C3**).
2. The account used and the device.
3. The time in Philippine time.
4. What you expected and what actually happened.
5. A screenshot. Also the version from More → Diagnostics.

## 5. After the test

The test school and its data stay in QA. C5 deletes the class, so the school is back where it started and the scenario can be run again.

*Scenario written 4 October 2026. Run by a person in the app and passed on 4 October 2026 (the automated API run was green the same day). A screen issue was found and fixed afterwards: the "name already exists" text stayed after the name was changed. Re-run on build 1.0.0 (5) on 4 October 2026: the text now disappears as intended.*
