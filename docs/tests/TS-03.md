# Test scenario TS-03: Invite a teacher, give them a class, suspend and remove them

| | |
|---|---|
| **Purpose** | Verify that a school admin can invite a new teacher, that the teacher can sign in and out, that the teacher gets a class and sees only teacher functions, that a suspended teacher cannot sign in, and that a teacher can be removed. |
| **Environment** | QA (the QA build of the Android app) |
| **Roles covered** | School admin (existing), teacher (new) |
| **Time needed** | About 30–40 minutes |
| **Background** | [roller.md](roller.md) explains the roles. TS-02 does the same for a school admin. |

---

## 1. Entry requirements

If something is missing, stop and report it. Do not work around it.

| # | Requirement | How to check |
|---|---|---|
| E1 | One Android phone with the QA build installed (version 1.0.0 (3) or later). Write down the version shown under More → Diagnostics. | The app opens and shows the sign-in screen. |
| P1 | A test school with a school admin: **SA1**. | Ask the Virtual School team. |
| P2 | A Google account, **T1**, that is **not** staff at the test school and is **not suspended**. T1 may have a role at a *different* school. SA2 from TS-02 can be used if it was removed and switched on again. | Ask the Virtual School team. |
| P3 | The test school has at least one class that has **no homeroom teacher** ("Not assigned" under Classes). | SA1: "Classes". |

**SA1** and **T1** both use the phone, one after the other. To switch accounts on the phone: tap the account button at the top right → "Sign out", then sign in with the next account.

---

## 2. Steps and expected results

Mark each step **Pass** or **Fail**. Text in "quotes" is the exact button or screen text.

**Automated column.** The Virtual School team runs these steps against the QA backend after each deploy (about 80 seconds, 24 checks, including all the "nobody may get more access" checks). **API** = the backend rule is checked automatically, so you only need to confirm that the app *shows* the expected result. **Manual only** = nothing checks this step automatically; do it carefully. Ask the team whether the latest automated run was green before you start. If it was not, stop and report it.

### Part A – Invite (SA1 App, T1 App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| A1 | **SA1 (App):** sign in. Open "Staff". | T1 is **not** listed under "Teachers". | API |
| A2 | "Invite teacher" → choose "Write it down". | A code in the form `ABC-DEF-GHJ` is shown with "One-time · valid for 14 days". Write it down for T1. | API |
| A3 | **T1 (App):** sign in. T1 has no role yet, so More shows "You're signed in, but this account doesn't have access to a class yet…". Tap "Have an invite code?", type the code from A2, but **change one character**, and tap "Continue". | "That code does not look right. Please check it against your slip." | API |
| A4 | Type the **correct** code into the three boxes (small or capital letters do not matter; the dashes between the boxes are only decoration, and a code pasted into the first box fills all three) and tap "Continue". **Do not tap "Join" yet.** | "You are invited" – "Join <school name> as a teacher." | API |
| A5 | **SA1 (App):** "Staff" → pull to refresh. | T1 is **not** in the list yet. | API |
| A6 | **T1 (App):** tap "Join". | "You're now a teacher" – "You have joined <school name> as a teacher." A "Continue" button is shown. | API |
| A7 | **T1 (App):** tap "Continue". Then open More → "Have an invite code?" and type the same code again. | The old code gives "This invite is not valid." *(A used code is deleted, so it looks the same as an unknown code.)* | API |
| A8 | **SA1 (App):** "Staff" → pull to refresh. | T1 is now listed under "Teachers", with the email and "No homeroom class". | API |

### Part B – A teacher without a class (T1, App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| B1 | **T1 (App):** go to More. | "You're listed as a teacher but have no classes assigned yet. Ask your school admin to assign you to a class." *(Record anything else that is shown.)* | API |
| B2 | Check the tabs at the bottom. | There is **no** "Staff", "Classes" or "Calendar" tab, and no "School settings" under More. | API |
| B3 | Tap the account button at the top right → "Sign out". Then sign in again as T1. | T1 is signed out and the sign-in screen is shown. After signing in again, the same text as in B1 is shown. | API |

### Part C – Give the teacher a class (SA1 App, T1 App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| C1 | **SA1 (App):** "Classes" → open the class without a homeroom teacher (P3). Under "Homeroom teacher" choose T1. | T1 is shown as the homeroom teacher. No error. | API |
| C2 | **SA1 (App):** "Staff". | T1 is listed with the name of the class instead of "No homeroom class". | API |
| C3 | **T1 (App):** More → "Reload". | The class opens with the tabs "Roster" and "Messages" (and "More"). The learners of the class are listed. *(Record the tab names.)* | API |
| C4 | **T1 (App):** More. | The class menu is shown: "Invite guardian", "Invite learner", "Enrol a learner", "Subject teachers" and the codes list. There is still **no** "Staff", "Classes" or "Calendar" tab and no "School settings". | API |

### Part D – Suspend (SA1 App, T1 App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| D1 | **SA1 (App):** "Staff" → tap T1. Switch "Account active" **off**. | "Suspended — this person cannot use the app." In the Staff list T1 is marked "Paused". | API |
| D2 | **T1 (App):** sign out and try to sign in again. | T1 **cannot** use the app. The screen says "Your account has been suspended. Contact your school administrator." with the buttons "Try again" and "Sign out". *(It must not say that the sign-in has expired. Allow up to 1 minute after D1 for the block to take effect.)* | API |
| D3 | **SA1 (App):** "Staff" → tap T1 → switch "Account active" **on** again. **T1 (App):** wait 1 minute, then sign in again. | The class view opens as in C3. *(Do not skip this step. A suspended account stays suspended after the teacher is removed, and nobody can switch it on again from the app. T1 could then not be invited again.)* | API |

### Part E – Remove (SA1 App, T1 App)

| # | Action | Expected result | Automated |
|---|---|---|---|
| E1 | **SA1 (App):** "Staff" → tap T1. Look at "Delete teacher". | "Delete teacher" is greyed out, with "Remove <name> as homeroom teacher first, then delete." | API |
| E2 | Tap "Remove homeroom class" and confirm. | The question "Remove the homeroom teacher from <class>?" is shown first. After confirming, the detail page shows "No homeroom class". | API |
| E3 | **T1 (App):** More → "Reload". | The class is gone. The text from B1 is shown again. | API |
| E4 | **SA1 (App):** tap "Delete teacher". | The question "Remove <name> from the school?" is shown. | API |
| E5 | Cancel. | Nothing changes. T1 is still listed. | Manual only |
| E6 | Repeat E4 and confirm. | T1 is no longer under "Teachers". | API |
| E7 | **T1 (App):** More → "Reload". | T1 has no school and no teacher functions. The text "You're signed in, but this account doesn't have access to a class yet…" is shown. *(Record what T1 sees. If T1 has a role at another school, that school may show.)* | API |
| E8 | **T1 (App):** More → "Have an invite code?" → type the old code from A2. | "This invite is not valid." | API |

---

## 3. Pass criteria

The scenario **passes** when all of the following are true:

- Every step is marked Pass, except those that say "Record".
- No step showed a technical error ("Something went wrong", a number such as 403 or 500) unless the expected result said so.
- D3 passed. T1 can sign in again after being switched on.
- The checks that nobody may get more access than they should all passed: A3, A5, A7, B2, C4, D2, E3, E7 and E8. **Any failure here is serious. Report it first.**

## 4. When a step fails

Write down:

1. The step number (for example **C3**).
2. The account used and the device.
3. The time in Philippine time.
4. What you expected and what actually happened.
5. A screenshot. Also the version from More → Diagnostics.

## 5. After the test

The test school and its data stay in QA. T1 is removed in E6 and the class has no homeroom teacher again, so the scenario can be run again with a new code.
